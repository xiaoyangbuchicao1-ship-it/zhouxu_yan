## 本次改了什么，为什么

人员列表支持按邮箱或称呼搜索、按角色和状态筛选，每页显示 20 人。业务记录单独切换，不再被几百行人员列表推到页面底部。手机使用紧凑列表，不需要横向拖动才能找操作按钮。

停用、启用和角色调整先让管理员确认，记录显示操作人、目标账户和修改前后。加载失败会显示重试入口，不会伪装成“0 人”。修改已经成功但刷新失败时，保留服务端确认的新状态，单独提醒刷新，不重新发送修改。

复查还修了两个后端根因：停用、退出或登录过期后，已经打开的回答连接也停止接收；旧事件入口只发送当前授权会话所属任务的事件，不能混入其他会话。连接检查直接读取最新权限，不缓存撤权结果，也不为每段文字反复写数据库。断开连接不会取消已有后台任务。

前端参考 [Framesbase Data Table 1](https://framesbase.app/reactbits-pro/app-ui/data-table/data-table-1) 的搜索、筛选、分页和手机布局，继续使用项目已有的 Radix 交互与深色配色，没有引入另一套组件库。截图检查发现过默认组件样式覆盖自定义样式，已从选择器作用域修复，并补进真实浏览器检查。

正常登录、人员修改和业务记录均走本机实际网站与真实 HTTP 服务。网络失败和过期响应由浏览器明确模拟，不能当作生产环境发生过这些故障。最终脚本五组全通过，两次运行新建的验收账户均恢复为正常普通用户并保留测试记录；没有删除原有用户或运行历史。本节点没有调用付费模型。

## 额外的连接权限检查

五项后端连接测试使用临时数据库、真实 uvicorn HTTP 服务和固定测试任务快照，分别验证：

1. 停用后，两种已打开的回答连接都停止。
2. 退出登录后，旧连接停止。
3. 登录过期后，旧连接停止。
4. 一个会话收不到其他会话的事件。
5. 高频权限检查不会反复更新数据库中的登录活动时间。

上述测试修复前已失败、修复后全通过。固定任务快照只用于验证连接与权限，不代表生产模型执行测试；没有调用模型，也没有更改正式库。
