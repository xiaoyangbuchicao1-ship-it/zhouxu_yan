# C3：按 CC Switch 思路接通中转模型的验收

日期：2026-11-21  
入口：`http://127.0.0.1:18080`

## 这次修了什么

Claude 的真实流式请求暴露了一个根因：中转站在交付工具刚开始时会发送一个空的参数片段。旧代码把空片段当成坏 JSON，已经收到的回答因此被改判为“模型不可用”。现在空片段会被忽略，真正非空但损坏的 JSON 仍然会报错，不会悄悄当成成功。

这和 CC Switch 的处理方式一致：按协议保留原生工具帧和续接状态，再把工具结果接回同一个模型请求。没有另起一套工作流或代理服务。

## 人话版验收

| 测试 | 测什么场景 | 防什么大坑 | 实际结果 |
|---|---|---|---|
| 空工具片段 | Claude 的交付工具先收到空片段，再收到正文 | 一次正常回答被误报成模型故障 | 通过；新增回归测试绿，旧解析器可稳定复现失败 |
| 三类协议问候 | GPT、Claude、Gemini 各发送一次“你好”，选择低档思考 | 页面改了档位，实际请求没带上；工具续接丢失 | 20 个中转模型真实完成低档思考、流式、工具调用和续接恢复 |
| 工作任务推进 | 三个模型分别开始“撰写海事论文并生成 PDF”，观察约 30 秒后暂停 | 一直停在准备阶段，或暂停后仍继续消耗 | GPT、Claude、Gemini 都进入了调用工具/查资料等真实步骤，并成功暂停 |
| DeepSeek 图任务 | 官方 DeepSeek 写入随机文字，再让模型读取并原样回复 | 图节点拿不到工具结果，或工具编号对不上 | 通过；随机文字原样返回 |
| 刷新与计时 | 问候完成后刷新页面 | 回答丢失、时间格式不统一 | 三类模型回答仍在；耗时保持一位小数 |

## 真实证据

- Docker Linux 合同测试：**38 项全绿**。
- 浏览器脚本：`tests/browser/c3-protocols.mjs --work-smoke`。
- GPT、Claude、Gemini 的问候、低档思考、工作推进、暂停、刷新均通过；浏览器没有脚本错误。
- 中转协议探测结果：20 个模型返回 HTTP 200 并完成完整 roundtrip；另外 7 个 GPT 型号当时返回 429 限流，因此本次不把它们算作新的通过证据。既有能力记录保留，不因一次限流把历史成功抹掉。
- 运行库只读检查：SQLite `quick_check=ok`；272 条运行记录、89787 条事件、272 条可见回答均保留，未清库、未改写历史正文。

## 一键体验

```powershell
docker compose --env-file deploy/app/.env -f deploy/app/compose.yaml up -d
```

打开 `http://127.0.0.1:18080`，选择 GPT、Claude 或 Gemini 中已显示“可工作”的模型，发送“你好”；需要验证工作链路时再提交论文任务，观察步骤出现“正在调用工具/查找资料”后点击暂停。
