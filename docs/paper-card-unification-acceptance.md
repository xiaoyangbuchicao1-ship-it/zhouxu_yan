# 论文资料统一验收记录

日期：2026-11-21

这次把论文资料统一换成了同一套 MinerU 卡片格式。当前正式索引只有 `maritime_information_cards_v4`：39,022 张卡，目录收录 1,145 篇原始论文。原 PDF、Markdown 和正文文件都保留，并逐篇核对了文件哈希；其中 1,144 篇有可检索卡片，另 1 篇仍可从论文目录打开原文。

旧卡的显示入口已迁到对应论文的整篇入口。历史回答正文、工具回执和原始文件没有被改写。旧论文索引 v1、v2、v3 已删除；正式卡片文件中旧 `info-atom-*` 数量为 0。SQLite 迁移使用了成对备份，备份目录为 `data/migrations/paper-cards-v4-20261121/sqlite-before`。

## 实际验收

以下测试都经过真实 HTTP 和 Chromium 浏览器入口，不是只调用内部函数：

1. 独立检索论文后打开摘录，页面定位到真实 PDF 页码；上一页、下一页、缩放和下载都正常。
2. 真实 DeepSeek 做一次很短的论文检索，回答中的论文引用能打开对应资料；资料栏按作者搜索后仍是同一篇原文。
3. 关闭页面再打开历史会话，资料栏和论文原文仍能打开；旧卡迁移后的整篇论文入口不虚构页码。
4. 未登录读取原文会被拒绝，伪造 PDF 版本号会被拒绝；下载文件的 SHA-256 与目录记录一致。
5. 手机宽度下仍能看到页码、缩放和下载按钮，PDF 真实画面可以显示。

浏览器验收 5 项全绿，页面错误为 0。过程结果目录已在正式迁入后清理；后端原文和迁移测试在 Docker Linux 中为 `Ran 4 tests ... OK`，正式发布文件与临时发布包的核心哈希已在清理前核对一致。Windows 直接运行会受 SQLite 文件锁和临时路径影响，不能代替支持的 Docker 测试。

本次还修正了阅读器的根因：Nginx 没有声明 PDF.js 的 `.mjs` 文件类型，浏览器因此无法加载阅读器 worker。现在 `.mjs` 按 JavaScript 返回，论文页面已实际渲染。

## 3A / 3B 原文阅读与全入口复验（2026-11-21）

### 这次修了什么

原文阅读器闪动不是重复下载，也不是接口反复报错。页面先放一个 `300×150` 的空画布，PDF 画完后画布突然变成真实大小，弹窗高度跟着变化，页面就会整体上移。现在阅读区域使用固定的可视高度，PDF 先在临时画布中画完，再一次性替换到可见画布；“正在读取页面”改成覆盖在画布上方，不再推动布局。翻页、缩放和窗口宽度变化继续保留旧画面，首次画完后才结束加载状态。
