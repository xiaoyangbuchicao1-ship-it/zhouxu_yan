## 根因与修复

- 模式确认原先把非拒绝文字当作同意；改为枚举校验，补充要求单独传递，旧提交入口复用同一规则。先持久化 Run，再更新会话投影。为模型增加只申请权限、不执行写入的控制工具，移除文件关键词推断。
- 上传与继续的按钮状态不一致，快速操作可能漏带附件；提交和按钮共用上传处理状态。浏览器脚本延迟真实上传请求，确认期间无法继续，上传结束后请求携带附件。
- 原摘要异常分支截断原文却声称全覆盖；改为完整原文引用并明确标注摘要未完成，编程异常正常暴露。固定预算内要求简短摘要，未加轮数或延长超时。
- 重复检索原先进入全局收尾并撤掉工作工具；第一次停滞仅停止重复工具分支，保留写作、写入与编译能力。Skill 完整指令作为必选上下文保留。
- 文件追加缺少跨进程动作凭据；以 Run/Action 身份记录写前/写后哈希和持久意图，原子替换后完成回执。崩溃窗口按实际文件哈希恢复，未知其他副作用明确报告，不能承诺所有外部操作恰好一次。
- 旧检查点基线与跨轮产物归属不明确；执行合同升级为 v2，并显式迁移，暂停/失败时也收集实际存在的文件，前端采用权威空列表清除失效产物。
- 异常诊断的事件阶段曾不符合合同，可能掩盖原错误；使用合法诊断事件，记录异常类型与堆栈位置，不把异常正文或凭证返回用户。

沿用既有 FastAPI/Pydantic、SQLite、调度器、React 与 Playwright；借用 LangGraph 的 checkpoint/显式 resume/副作用重放边界，不引入新工作流集群。未直接修改运行容器内的业务源码。
