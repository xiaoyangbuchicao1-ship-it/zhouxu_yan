## 真实业务比较

状态：D1 已通过整体验收；下面的新旧结果来自启用前的独立比较。其后用户明确批准整体切换，正式默认已启用相同内容。

使用 `tests/prompts/compare.py` 和 `tests/prompts/compose.yaml`，在独立 Docker Linux 容器中启动真正的 HTTP 服务。新旧两版都经过注册、登录态、公开任务入口、权限判断和任务调度；不通过内部 scheduler 代替用户入口。

两版固定官方 `deepseek-flash`、无思考、temperature=0，相同输入，每版最多 5 次模型调用。源码、语料、现有业务数据均只读，临时运行库放 tmpfs，测试账户、数据库和文件目录隔离，不挂载正式 `runtime-state`。未调用其他供应商模型，不生成长论文或 PDF。

| 场景 | 在测什么 | 成功条件 |
|---|---|---|
| 短改写与日期 | 普通办公请求是否直接、准确回答 | 只有要求的两行，截止日期与提单副本事项保留，没有多余检索和套话 |
| 单条法规 | 是否取得并引用实际现行条文 | 正文法名、条号、版本和真实资料匹配；通过 HTTP 打开对应来源并核对条文 |
| 短论文引用 | 回答中的论文链接能否回到所引材料 | 正文链接对应实际检索资料；HTTP 可打开，题名、作者、原文和页码可核对 |
| 授权与暂停续做 | 写文件是否先经明确授权，暂停后能否接着做 | 普通文字不能越权；同一 Run 保留原目标及补充；下载文件中三行内容各出现一次 |

法规工具当前提供可读出处，执行层生成资料卡标识；测试不要求模型猜测未提供的链接。论文工具提供 `citation_url`，因此论文场景必须检查实际正文链接，不能仅凭侧栏有资料就算回答已经引用。

用量统计区分实际取得的总 tokens 与缺失用量；没有输入/输出分项或账单单价时，不推算准确费用。单次短样本的耗时不等同于普遍性能提升。

本轮论文场景两版各 3 次模型调用，旧版 33,591 tokens、5.52 秒，候选 31,973 tokens、6.17 秒；用量均完整取得。候选少用 1,618 tokens，但慢 0.65 秒。这个差异来自一次短样本，不能当成普遍性能结论。

主观评价（只评价这次论文引用回答的清晰度、完整性和可核对性）：旧版 **8.4/10**，候选版 **9.0/10**。两版事实和引用均正确；候选版把作者、题名、年份和观点分开写，阅读更清楚，也少了一些重复表达。评分本身不是启用操作；正式切换依据是用户后续的明确批准。

### 论文链接根因修复

首轮失败已用无模型调用的确定性回放复现：`PublicText.render()` 对全文直接替换内部 `resource_id`，把合法 Markdown 目标 `/workspace/sources/paper-info-pdf-…` 的一部分也替换成显示文案。逐字流式回放会得到同样的坏链接，根因在平台文字处理，不在提示词，也不是资料没有检索到。

修复后只对真实论文工具返回、并通过格式核对的完整 Markdown 链接目标做保护；普通正文和链接标题中的内部编号仍会隐藏。普通工具结果、工作流工具结果、流式分片、最终回答和历史回答共用这条规则。论文原文读取还改用 `cards.offsets.json` 偏移索引：首次打开 2.23 亿字节、39,022 张卡片由约 210 秒降到约 0.44 秒；索引缺失或损坏会直接报错，不再静默全量扫描。发布脚本会在发布卡片时生成索引。

修复后的确定性测试和真实浏览器验收均通过：正文引用点击、刷新后再次点击、PDF 页码/翻页/缩放、下载校验、手机宽度和页面错误检查全部通过；真实新旧对比的论文场景 24 项检查两版均通过。D1 当时保留候选未启用；后续直接切换记录见下方。
