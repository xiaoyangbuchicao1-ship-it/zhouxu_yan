# P0-E Node 1 验收记录

日期：2026-11-22

这一节点只建立“谁是谁、能不能进入管理员入口”的后端基础，还没有制作管理员工作台页面。

## 做了什么

- 账户增加 `user` / `admin` 角色。
- 新注册账户固定是普通用户。
- 新增 `/auth/admin-login`，只有管理员账户能通过。
- 登录响应和 `/auth/me` 都返回角色。
- 旧关系库增加 `role` 列，225 个历史账户保持原资料和会话关联，统一按普通用户处理。
- 管理员初始化只读取部署环境的 `ZHOUXU_ADMIN_EMAIL` 和 `ZHOUXU_ADMIN_PASSWORD`；密码只保存 Argon2 哈希，不写入代码、文档或日志。
- 管理员已经存在时启动不会悄悄改密码；同邮箱如果是普通账户会明确报冲突。

## 黄金测试（人话版）

### 1. 新用户默认是普通用户

- **测什么场景**：一个新用户注册，然后重新确认登录身份。
- **防什么大坑**：如果新用户被误当成管理员，所有后台权限都会失守。
- **预期效果**：注册结果和会话身份都显示 `user`。

### 2. 管理员初始化可以重复启动

- **测什么场景**：服务启动两次，使用同一组部署管理员环境变量。
- **防什么大坑**：每次启动重复建号，或悄悄覆盖管理员密码。
- **预期效果**：两次得到同一个管理员账户；已有密码不会被静默替换。

### 3. 普通用户不能走管理员入口

- **测什么场景**：普通用户拿自己的邮箱和密码请求管理员登录。
- **防什么大坑**：只在页面上隐藏入口，但后端实际放行普通用户。
- **预期效果**：管理员登录失败，普通用户仍能正常登录普通入口。

### 4. 旧账户迁移不丢资料

- **测什么场景**：把一份只有旧字段的账户库迁移到新结构。
- **防什么大坑**：为加角色清库、重建表，导致历史账户和业务记录消失。
- **预期效果**：原账户数量和内容保留，新列统一为 `user`；正式迁移另留有完整性通过的回滚副本。
