# 海事案例库的正式接入

案例是独立资料源，沿既有 Action → Run 记忆 → 感知 → 主模型路径工作。
`search_cases` 找类案，`read_case` 按字符范围读原文。法规工具保持原有版本协议。
三档 Harness 共享已有 BGE-M3 实例、单线程编码队列和认证 OpenSearch 客户端；没有第二份模型常驻。

当前快照为 `case_eb1be2c7fa1cd1fb`，825 案、3156 块，正式数据在
`data/cases/case_eb1be2c7fa1cd1fb/`，与实验目录无运行依赖。
文件含完整本地原文、规范化分块、原始向量和校验清单。资料不随 Git 发布；部署须单独提供经授权的数据包。

## 准备与发布

从工作区根目录使用已安装 rag extra 的 Python：

```powershell
python -m backend.infrastructure.corpus.prepare_cases SOURCE NEW_DESTINATION
python -m backend.infrastructure.corpus.import_cases
```

第一步适配交付包的中文字段，校验向量与分块逐行身份、原文字面范围、非空白正文覆盖及原始向量归一化；不会重算或替换原向量。目标目录必须不存在。已在当前原包上重建，四个输出文件与正式快照逐字节相同。

将 `config/defaults.toml` 的 `cases.snapshot_dir` 指向所选快照后再执行第二步。第二步复用 `rag` 的 TLS、主机白名单及凭证读取；不输出凭证。它创建独立物理索引，以 `_meta` 校验快照与清单，在 bulk 成功、计数完整后原子更新 `cases.read_alias`。禁止使用法规别名。应用启动只读检查，不执行建库或切换别名。

现有快照索引不会被覆盖。半成品、错误清单或失败分片不发布；应由运维定位失败后显式处理未发布索引，不能用重试静默覆盖现有来源。先备份数据包、配置与索引，再更新。当前开发集群是单节点、零副本，不能当成高可用生产部署。

应用按启动时的数据包固定物理索引，不在 Run 中途跟随别名漂移。升级时先结束/暂停活动任务，再配套切换快照、发布并重启；回滚也需恢复同一组快照配置。旧版读取请求与当前版本不符会明确失败；尚无跨版本自动读取注册表。保留旧包和旧索引，不做自动删除。

## 检索与来源

- 每路取 50 块，BM25 使用 `title^3` 与 `text`，向量为固定 revision 的 CLS/L2 1024 维。两路同快照过滤。
- 每路先按案例去重，默认保留各路前三个候选，向量优先交错，再按案例 RRF 补齐，默认六案。
- 搜索回执给原文摘录和实际范围；需要补充时按 `next_start` 续读。全文读取包含重复段落，不强制读完整案。
- 每条回执保留案例 ID、快照、正文 SHA256、字符范围及可读引用。返回分块与本地原文不符则失败，不能继续引用。
- 原始法院等元数据隔离保留，不作为过滤或自动引用来源；只有原文头部可逐字定位的法院/案号进入 `supported_identity`。这只是本地字面支持，不是官方认证。日期保持未知，不能按叙事猜测。
- 案例可含原判、摘要和评析，主模型须区分主体与历史法。检索成功、引文存在都不能证明法律推论正确。

工具回执遵循既有预算。当前 Run 可见正文，跨轮只留来源；摘要明确“历史读过”和“本轮正文可见”不同。故障、来源不符、预算不足与无命中分别处理。编码器不可用不静默退为 BM25。
