# 海事案例检索与解析

这个 Skill 描述业务流程和证据边界。案例库、法规库、用户材料都通过现有 Harness 工具访问；Skill 不直接调用 OpenSearch、数据库或文件系统，也不复制工具实现。

## 适用时机

当用户寻找海事类案、比较裁判事实或理由、核对某个案例的处理方式时使用。一般问答、用户已经提供且足够的材料整理，不为了形式而检索案例。

## 执行顺序

1. 用一句话固定本次案例问题、事实范围和需要比较的要点。
2. 调用 `search_cases` 找候选，保留返回的 `reference_id`、`case_id`、`snapshot_id` 和原文范围。
3. 只读取会影响当前判断的范围；候选片段不足时调用 `read_case`，不要为了“完整”机械读取全文。
4. 输出时分别标记：当事人主张、法院认定、案例评析或来源作者观点、舟序基于当前证据的推论。
5. 案例原文引用的法条属于当时语境。涉及现行规则、版本或效力时，另调法规 RAG，并把法规依据与案例依据分开列出。

## 证据边界

- 排名和相似度不是法律支持度，不能把命中候选直接写成结论。
- `law_effect`、法院、日期、案号等字段未被当前原文或工具结果支持时保持未知。
- 案例库无命中不证明现实中不存在；服务失败不改写为空结果。
- 引用具体案例必须带可读的 `reference_id` 或工具返回的 citation，并保留来源快照关系。
- 不把历史案例引用的法条自动替换成现行条文，也不把案例事实当作用户事实。

## 输出建议

先给与问题直接相关的结论或比较，再用简短分组说明事实、裁判理由、依据与未解决缺口。只有在用户要求或确实有助于核对时，才展开原文范围；不要倾倒内部索引字段。

工具状态必须如实呈现：`empty`、`failed`、`unavailable`、来源校验失败和证据不足分别保留，不以模型自述“已检索”替代真实回执。
