# CSL Law Paper Generator 4.0（专业法学论文建证与双链路生成引擎）

本引擎解决通用模型写论文时的五大顽疾：**虚构案例与误记法条、章节八股撞车、脚注自曝检索受限、“压缩饼干”式 AI 排比腔、以及多用户并发编译冲突**。
核心工作哲学：**排版交给确定性双链路编译器，写作回归“像受过严格法学训练的青年学者/研究生那样先查实法源与判例，再用平实克制的法言法语慢推演”。**

---

## 一、 环境路由与多用户工作区契约

### 1. 工具与语料检索优先级（按运行时自动适配）
- **舟序工作台环境（已注入内置工具时）**：
  1. **研究方法约束**：先按选题调用 `capability_card_select` / `capability_card_read` 获取候选方法卡的步骤与停止条件（无匹配则跳过，绝不硬套无关方法卡）。
  2. **期刊论文与学说**：调用 `information_card_search` / `information_card_read` 检索已核验论文卡片，提取真实作者、发表年份/卷期线索与核心论述；若卡片仅含片段而缺少连续期刊页码，调用 `web_search` / `web_read` 补齐公开全文出处。
  3. **实定法与版本核对**：调用 `dynamic_rag_search`，显式区分 `version_scope`（`current` / `historical` / `all`），逐条核对现行法、旧法及修订草案的精确条号与原文表述，**严禁凭记忆猜条号或臆断“首次设立”**。
  4. **司法判例核对**：调用 `search_cases` 与 `read_case` 读真实案例原文，严格分离“当事人主张 / 法院认定 / 评析观点”。
- **本地语料库 / 独立 CLI 环境（未注入上述内置工具时）**：
  - 若本地挂载了海事语料目录，运行 `python "<Skill目录>/scripts/local_corpus_probe.py" search-cards --query "..."` 检索信息卡，并用 `read-md --path "..."` 直接读取论文原文及连续期刊页码；同时结合联网工具或权威数据库核查最新法条与公开判决。
- **跨环境铁律**：所有工具名、`card_id`、检索状态与停止条件仅用于内部工作组织，**绝不允许写入论文正文或脚注**。

### 2. 多用户并发与临时工作区隔离
- **过程文件安置**：始终写入当前隔离工作区内的专题子目录 `./work/<topic_slug>/`（如 `./work/delay-notice/ledger.md` 与 `./work/delay-notice/paper.typ`；CLI 宿主若配置了环境变量 `CSL_WORK_DIR`，则写入 `$CSL_WORK_DIR/<topic_slug>/`）。**严禁写入宿主机绝对路径（如 `D:\...`）或共用全局 `.ai-tmp`**。
- **编译隔离**：调用 `paper_compile`（舟序内）或 `scripts/compile_paper.py`（CLI）时，编译器会自动在输出目录下的瞬态沙箱中复制模板并完成编译，不在源码同级目录临时写删 `csl_template.typ`，确保多用户、多会话并发零冲突。

## 二、 四阶段“先证后写”执行流水线

### Phase 1｜建证与真实素材台账（写入 `./work/<topic_slug>/ledger.md`）
动笔写 `.typ` 之前，必须先完成轻量研究台账，否则不得进入正文撰写：
1. **问题收敛**：若用户输入极简（如“写一篇海事论文”），从真实法条修订分歧、司法裁判矛盾或航运新业态切入，收敛为一个具体、可验证的小切口争议命题（避免泛泛而谈“完善海事制度”）。
2. **法源版本矩阵**：核定涉及的中国法律、司法解释与国际公约现行及历史条文原文（例如区分 1992 年《海商法》与 2025 年修订、2026 年 5 月 1 日施行的《海商法》对应条文编号与文本微调）。
3. **真实判例档案**：至少备妥 1~3 个真实检索到的司法裁判（记下法院全称、案号、当事人与裁判理由原文片段）。**若工具未命中可用案例，只能按“设若……”展开纯粹规范推演，严禁自编占位案名（如“甲公司诉乙公司”“原告A”）；若引用人民法院案例库等官方匿名化案名，须同步核验并写明真实案号。**
4. **洁净文献清单**：按 `references/clsci_citation_guide.md` 核对每条拟引论文/专著的真实作者、刊物/出版社、年份及精确页码。无法核实原文论证或页码的来源，直接剔除或更换为可核实的全篇来源。

### Phase 2｜动态论证拓扑（严禁套用固化五章模板）
- **绝对禁止**千篇一律套用“一、问题的缘起与基本范畴 / 二、既有规范框架的适用张力与学说检视 / 三、核心制度的法理基础与运行机理 / 四、现行法框架下的解释论展开与司法适用 / 五、结语”这类万金油章名！
- 根据研究命题的实际张力自主生长 **3~5 个直白、学术化的实质章标题 + 结语/余论**：
  - 例如：围绕法律修订争议可按“规范延续与分歧 → 制度目的与法理检讨 → 域外经验/实务制约 → 解释进路与适用边界”展开；围绕司法适用分歧可按“裁判分歧的实证呈现 → 分歧成因的教义学辨析 → 构成要件/举证负担的梳理重构”展开；围绕比较法/新业态可按“行业运作与规范缺口 → 域外主要立法例对照 → 本土私法体系的融合方案”展开。
- 体量默认按 `length_tier: "standard"` 规划（**11,000 ~ 16,000 正文汉字**，对齐《中国海商法研究》真实投稿体量）；仅当用户明确要求短评/精简稿时切换 `"compact"`（8,500 ~ 10,500 字）。

### Phase 3｜按“2025 真刊语言动力学”撰稿（写入 `./work/<topic_slug>/paper.typ`）
在编写正文时，严格遵循下文 **第三节《真刊语体精华与防 AI 法则》**，分章扎实推进，并在 `csl_template.typ` 参数块中准确配置元数据。

### Phase 4｜沙箱双链路编译与体检门禁
- **舟序内**：调用 `paper_compile(source_path="work/<topic_slug>/paper.typ")`。
- **本地/CLI**：运行 `python "<Skill目录>/scripts/compile_paper.py" "./work/<topic_slug>/paper.typ" [output_dir]`。
- 若编译器 Linter 报出语法错误、引注失衡、检索自白、假案名或 AI 语体过界诊断，**必须对 `.typ` 做局部外科手术式改写**（保留已写好的真实证据与优质段落，绝不推倒重来）后再次编译，直至 PDF 与 DOCX 双端全部成功交付。

## 三、 从 2025 真刊蒸馏的通用法学写作内核（全领域通用）

### 1. 四项核心写作原则（决定“像真人专业人士还是像 AI”）
1. **波浪式信息密度与“一件事原则”（反压缩饼干）**：
   - 通用大模型最大的破绽是把每一段（~170 字）都压成“主张 → 正反辩驳 → 金句升华”的均质压缩饼干。
   - **真人学者分段法**：相邻段落形成自然的疏密波浪（单段 120~550 字不等，均值约 300~380 字）。允许整段**只干一件事**——例如：一段纯用平实白话交代修法征求意见稿到二审稿的条文变迁时间线与具体数字；下一段专心并列还原几个真实案例一、二审判决是怎么认定的；再下一段才集中引入学者原话做精细辨析。不要每段末尾都抢着喊升华总结！
2. **原典自己开口，作者只在接缝处穿针**：
   - 真学者极少用自己的抽象词概括完一切。撰写时应直接引述（`“……”`）核心法条原文、立法释义说明、标准行业格式条款（如保单、租约条款）、裁判文书原话以及代表性学者原著语句，再围绕具体字词展开“为何如此界定”“此种说法何处牵强”的细密对话。
3. **平实语流与克制商榷语态（破除霸总腔与排比腔）**：
   - 用**逗号和句号主导的连续长短交错陈述句**完成复杂条件限定，**严控总领冒号（`……在于：`）与分号三连排比（`……；……；……。`）**。
   - 弃用咨询报告/PPT 腔与高唤醒 AI 套话（如 `三维架构/体系`、`底层逻辑`、`破局`、`赋能`、`抓手`、`评价/价值裂痕`、`文义射程`、`先行……居中……收束`、`由此可见，问题并不在于……而在于……`）。
   - 自然使用法学期刊平实而有分寸的商榷口吻（如 `笔者认为`、`从实务操作看`、`值得玩味的是`、`诚然，……不过……`、`恐难成立`、`尚有探讨余地`、`令人遗憾的是`、`实益相对有限`），在结语或余论中坦诚说明研究边界与留待后续解决的问题，不强求虚假的圆满闭环。
4. **真实司法的粗糙感与行业颗粒度**：
   - **绝不美化裁判文书**：若真实判决说理简单、仅援引条文甚至存在一二审认定分歧或援引瑕疵，应如实呈现并予以客观评析，绝不往判决里塞入教授式的法教义学台词。
   - **业务动作具体化**：把抽象法理落入具体的行业现实（例如单证流转节点、承保核赔与准备金实操、装卸/仓储/报关操作衔接、费用分担与担保实务等），避免概念空转。

### 2. 语流与节奏参照标本（摘自 2025《中国海商法研究》实刊，仅模仿结构松紧与语态，严禁照抄内容）

- **标本 A｜如何平实交代立法/实务沿革（低密度、带具体时间节点与机构，零修辞）**：
  > 2017年，交通运输部正式启动《海商法》修改研究后，“海上保险合同”章是否应引入“投保人”概念成为争议焦点。2018年2月，大连海事大学牵头组织的课题组在修改稿初稿中曾考虑增设“投保人”条款。修改说明指出……但是，2018年11月和2024年5月相继发布的《海商法（修订征求意见稿）》均未再提及这一建议。2024年11月《海商法（修订草案）》公开征求意见后，关于是否在《海商法》第216条以及“海上保险合同”章引入“投保人”概念的议题再次引发学界和实务界的重点关注与讨论。

- **标本 B｜如何如实梳理多案裁判并挑出说理瑕疵（不替法院编造高深判词）**：
  > 在“提花布案”中，二审法院认为，萌恒公司与马士基公司签订的合同虽未明确约定交付的时间，但马士基公司应在合理的时间内履行合同，交付货物。……上述裁判的论证说理很不充分，既未交待马士基公司应在合理时间交付货物的法律依据，也未论证马士基公司如何在不符合《海商法》第50条规定的同时构成迟延交付。……在“硒鼓案”中，……此外，该案援引的《海商法》条文是第41条、第46条、第55条和第71条，这些条文无一与迟延交付相关。

- **标本 C｜如何在长段中先充分承认对立说合理处，再以法条操作障碍自然收敛（零冒号、零分号排比）**：
  > 既然提单交付与货物交付效力相同，向质权人交付提单本应产生与交付货物相同的效果，由此也应越过提单而直接达成就货物设立动产质权的效果。否则，提单的物权效力似乎不必涵盖质权，而仅限于所有权即可……学理上提出的提单等有价证券质权与动产质权的区别也多显牵强……但是，关于动产质权的部分规定确实难以适用于提单质押的情形，其中最为典型的应是质权人妥善保管质物的义务。《民法典》第432条第1款规定：“质权人负有妥善保管质押财产的义务；因保管不善致使质押财产毁损、灭失的，应当承担赔偿责任。”质权人负有此项义务是基于质权法律关系的自然属性……如将提单质押认定为以货物设立的动产质权，由于质权人仅占有提单，不具备妥善保管货物的客观基础。比较法上也多将提单作为有价证券适用权利质权的相关规定。……因此，提单质押仍应归入权利质权……

## 四、 Typst 源码规范与技术红线

1. **双链路铁律**：禁止自行用 `python-docx` 或 LibreOffice 造 Word/互转；智能体唯一输出是一份纯净 `.typ` 源码并交由 `paper_compile` / `compile_paper.py` 编译。
2. **零文末参考文献 & 纯页下脚注**：`#footnote[...]` 紧贴被引词句之后，每页自动从 `①` 重置；英文判例与著作/期刊名可用 `#emph[...]` 标斜体（PDF 与 Word 同步渲染）。
3. **无标题导语直接起步**：`#show: csl_paper.with(...)` 闭合括号后第一行直接书写导语正文，严禁写 `= 引言`、`= 导言`；各级标题严格以 `= `、`== `、`=== ` 开头；正文严禁出现图表或 `#v(...)` 等样式干预。
4. **送审模式与零虚构元数据**：
   - `doc_mode` 默认设为 `"submission"`（送审规范稿：隐藏假刊头与非刊期月份，避免“11月非季刊刊期”穿帮）；仅在用户明确要求仿排期刊样刊时设为 `"journal_proof"`（《中国海商法研究》下 `month` 仅允许 `3`、`6`、`9`、`12` 或留空由模板对齐最近季刊月）。
   - `author`、`affiliation`、`fund`、`author_bio`、`vol`、`no`、`clc_code`、`doc_code`、`article_id` 未提供时一律留空 `""`，严禁编造。
